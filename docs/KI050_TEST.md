# 单项积分提速试验

版本`v0.5.0-ki050-test`。基于`v0.4.0-trace-analysis-test`，上一个固件参数为Kp/Ki/Kd=0.8/0.25/0.02。

## 检查结论与改动

Control_StartHold捕获当前舵机输出为固定bias，位置式PID输出为bias + direction*(P+I+D)，方向-1。底座发生持续偏转后，比例项随误差消除而减小，积分项需要提供保留的补偿；Ki=0.25时补偿积累较慢。现有记录中输出没有限幅/限速饱和，未见需要再提高限速的证据。这是参数选择与记录相符的解释，不代表传感器和机械问题已全部排除。

仅将Application/app_config.h中APP_HOLD_NORMAL_KI从0.25改为0.50。Kp0.8、Kd0.02、死区0.5°、限速180°/s、方向-1、20ms控制周期、抗积分饱和、故障锁存、OLED局部刷新及串口协议均不变。不将位置式PID改成每周期累加输出，也不加入底座前馈；IMU仍须随连杆安装。

提高Ki可能增加过冲和低频摆动，本版为试验版，不能直接替代已验证稳定基线。此前IMU_INVALID尚未修复，保护没有放宽。

## 软件检查

control及app_integration主机测试通过。现有模型覆盖0～180°目标范围、方向、单步限速、输出范围、重复样本不积分、过期/无效样本/调度超时锁存等。

同一个8°底座阶跃和一阶执行器模型：Ki0.25为11780ms，Ki0.50为6420ms，均包含进入±1°后连续保持1秒的确认时间。这不是实际SG90速度预测，不能宣称实物必然快一倍。助手未执行Keil编译或烧录。

## 用户编译及上板验收

1. 关闭HOLD并停止TRACE。保持IMU随连杆固定，底座水平、手动90°对应连杆竖直。由用户在Project/eXin.uvprojx中Rebuild后下载，等待静止校准完成。
2. 开启HOLD，设置并确认约90°目标，查询SERVO HOLD ?确认ON、FAULT=OFF，目标/实测接近90°。先静置10秒，观察是否出现新增摆动。
3. 开TRACE并记录新CSV，另存为trace_ki050.csv。开始时水平静置2秒，再在底座一侧放入小支撑物，倾角约5°，松手后一直保持支撑，不再触碰或放回水平。记录至少30秒，停止记录和TRACE。
4. 口头估计放置耗时可以记录，但不要当作精确松手时间。本次先看固定底座后的误差收敛形状、最终误差和是否反复跨过目标；要比较准确恢复时间必须标记真实松手时刻。
5. 请反馈编译结果、静止是否摆动、放好后偏差消除是否更快、是否有明显过冲/持续摆动/IMU_INVALID，并提供CSV。不要同时改变安装、供电或其他PID参数。

若出现持续摆动、明显恶化或接近机械限位，关闭HOLD，保留数据。若出现IMU_INVALID，重新开启前先查询SERVO HOLD ?、IMU RAW ?、IMU FAULT ?，不要用这次锁存停机判断积分效果。用户不必为完成测试继续顶住机械限位。

## 备份与回退

Git标签v0.5.0-ki050-test，源码包backups/v0.5.0-ki050-test.zip。回退本次调参可取v0.4.0-trace-analysis-test（含已验收OLED及分析工具，Ki0.25）；整套历史稳定回退点仍为v0.1.0-stable。取旧源码后需要用户Rebuild及烧录才会改变板端参数，不能仅切换电脑文件就认为板端已回退。
