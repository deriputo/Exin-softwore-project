# v0.9.1：2°过冲预算下的跟踪提速候选

用户明确允许最大短暂过冲2°，优先持续翻转底座时的跟踪速度。这里的2°是固定目标、单次扰动后的反向过冲上限，不是承诺任意连续翻转时的误差都小于2°。

## 源码改动

位置纠偏系数保持0.30；执行器估计时间常数0.12→0.10秒；受限速度反馈系数保持0.06秒、50ms滤波，贡献上限3→6°。本次没有新增算法。旧PID Kp不参与当前DIRECT+。

原因：先扫描972组，再扩大至972组候选；增大位置系数的组合未在原144组正向失配筛选和2°过冲条件下获得更好的综合恢复/跟踪表现。不能为了形式上的加Kp交付更差参数。因此选用更快跟进的现有结构。两轮网格局部有重叠，不代表穷尽全部可能参数。

原±0.5°死区、0～180°目标/输出、180°/s限速、20ms周期和全部故障保护保留。OLED仍显示HOLD Y DIRECT+，不以此区分v0.9.0与v0.9.1；需要确认从当前源码Rebuild并下载。TRACE P/I/D语义同v0.9.0。

## 模型结果和局限

完整288组正反扰动/执行器/机械增益/测量延迟失配测试，最坏过冲1.88°，最慢进入±1°并保持2400ms。过冲测试门限从1.5°调整为用户批准的2°，不是在原1.5°条件下通过。

参考模型±5/15/30°扰动：v0.9.0进入±1°为820/1540/1980ms，本版700/1320/1740ms。改善约12～15%，并非一步到位。

新增12组连续正弦底座动作测试：幅值±10°、周期2/4秒，物理时间常数0.06/0.12/0.24秒，测量额外延迟0/60ms。评分使用物理模型真实姿态，非延迟测量；前4秒排除，统计至20秒。每组新版本RMS误差均小于v0.9.0，且无故障、输出越界或超限速。

例如物理时间常数0.12秒、无额外延迟、周期4秒，RMS误差3.604→3.285°；周期2秒为4.474→4.279°。可见仍未达到持续运动时紧贴目标，不能拿本模型结果宣称用户目标已完成。模型也不能保证实物过冲小于2°。

control_direct、control、app_integration通过。尚未Keil编译烧录或实物验收。IMU_INVALID根因仍未解决，保护未放宽。

## 用户验收

1. Keil打开Project/eXin.uvprojx，从当前源码Rebuild并下载。底座水平、输出90°连杆竖直，IMU牢固随连杆运动，静置完成校准。
2. 开HOLD，查询SERVO HOLD ?确认FAULT=OFF；静置20秒，先确认不持续摆动。
3. 开TRACE与CSV，只做一次约5°倾斜后固定保持10秒；再回水平并保持10秒。不要中途重新开HOLD。记下大致停止动作时刻，检查过冲是否超过2°。
4. 单次通过后另录CSV：保持HOLD目标不变，让底座在约±10°间连续缓慢往返3次，每次完整往返约4秒，最后放稳保持10秒。此过程中不要求你手绝对不抖，分析会保留手动输入影响的限制。
5. 分别反馈最大过冲、是否持续摆动、连续翻转时是否明显滞后、停下后是否继续明显修正，并发送两份CSV。若过冲超过2°或持续摆动，停止HOLD并反馈。
