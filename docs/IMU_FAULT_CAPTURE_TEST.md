# IMU_INVALID首次故障记录

试验标签：`v0.2.1-imu-fault-test`。继承180°/s限速版；P/I/D=0.8/0.25/0.02，方向-1，控制及IMU有效性保护未调整。

## 当前已确认与未知

用户故障现场查询：

```text
SERVO HOLD=ON FAULT=IMU_INVALID target=+87.2 measured=+130.6
RAW AX=+750 AY=+679 AZ=-50 mg GX=+0.1 GY=+0.1 GZ=+0.1 VALID=1 CAL=1 COUNT=200 AGE=0 REASON=NONE
```

这说明控制器此前锁存了无效样本故障，而查询时IMU已恢复有效。控制器在故障后保持最后PWM，不会自动恢复纠偏；measured仍随有效新样本更新，故130.6不是首次故障角度。目标差43.4°不能证明控制器还在工作。

旧版原因字段反映当前IMU状态，恢复后清空，不能据此确定是通信错误、采样过期或有效性检查失败。用户又补充“小幅摆动最后会停”，尚未确认停止是否早于故障，不能当作自然收敛已验收。

## 本次改动

新增扩展命令`IMU FAULT ?`，保留原规定命令及响应格式。HOLD首次进入故障的同一主循环保存：

- `LAST_FAULT`：当时控制器故障类型。
- `AT`：故障发生时板端毫秒时间，非电脑接收时间。
- `SRC`：当时驱动原因，或根据当时样本识别的有效性条件。
- `AGE`：故障当时样本年龄，单位ms。
- `VALID/CAL/COUNT`：故障当时的样本有效、校准状态、校准计数。
- `AX/AY/AZ`：故障当时保留的原始加速度，单位mg。
- `OUT`：故障后保持的PWM脉宽，单位us。

通信失败时保留的加速度可能来自最近一次成功读取，不能当作失败事务读到了这些数值。SRC是直接触发条件或驱动报告，不等于最终硬件根因。

后续数据恢复不会覆盖记录；HOLD OFF也保留记录。成功重新开启HOLD或复位会清除旧记录。无记录时回复`LAST_FAULT=NONE`。此命令电脑串口与蓝牙均可使用。

| SRC | 解释 |
|---|---|
| `READ NACK` / `READ TIMEOUT` / `READ BUS ERROR`等 | 保存驱动报告的阶段及错误，需要进一步查总线/供电/时序 |
| `SAMPLE_STALE` | 当时样本超过100ms；应用旧路径可能将其归为IMU_INVALID，本版仅记录区别 |
| `ACCEL_NORM` | 当时合成加速度未通过原有效性范围检查；记录原始值进一步判断 |
| `AXIS_PROJECTION` | 当时重力在控制倾角平面的投影过小，不能可靠获取该轴倾角 |
| `UNCALIBRATED` | 当时未完成校准 |
| `CONTROL_TIMING` | 控制循环超过既有时序门限 |
| `CONTROL_INPUT` | 其他控制输入无效，需结合记录继续诊断 |

## 用户测试

1. 用户在Keil中Rebuild并下载新版本。底座水平、连杆90°竖直、IMU随连杆固定，静置至校准完成。
2. 文本串口发送`IMU FAULT ?`，应为`LAST_FAULT=NONE`；长按K2或发送`SERVO HOLD ON`开启HOLD。
3. 先保持底座静止观察，再按之前能触发故障的动作小幅转动。观察摆动何时停止、停止时是否已经显示故障。不拔线、不人为制造断电来代替原故障。
4. 出现故障后，不复位、不重新开启HOLD，分别发送以下三条命令，复制完整回复：

```text
SERVO HOLD ?
IMU RAW ?
IMU FAULT ?
```

每条以实际CRLF结束。需要关闭HOLD时可关闭，首次记录仍保留；不要为查询记录继续让机构机械顶住限位。
5. 将回复和“停止摆动是在故障之前还是之后”告知助手，再根据SRC决定下一项修复。不直接放宽有效性检查或自动重新使能HOLD。

## 软件验证与状态

app_integration、protocol主机测试通过。覆盖：通信故障后恢复但保持原故障/PWM、当前M继续更新、首个原因与时间不可覆盖、OFF后保留/重新ON清除、采样过期/投影不足/加速度异常/未校准分类、电脑与蓝牙查询。

本版尚未由用户Rebuild/烧录或实物验收，没有宣称IMU故障根因已定位或已修复。
