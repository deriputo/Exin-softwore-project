# v0.10.2：PIDR限速时积分冻结修复试验

已先按用户要求独立保存慢速验收版本v0.10.1-pidr-slow-accepted，其控制源码与v0.10.0相同，快速突变已知不合格。本版本另存标签，不覆盖慢速验收标签。

## 已定位的软件缺陷

用户stm32_trace6.csv共764帧/38.15秒，fault全为NONE，但存在长时间大误差、I不变、输出只随P微调的状态。例如约20.5～24秒，实测约40～43°、目标90°，I一直-25.7。快速突然转动出现，慢速可正常工作。

原PID抗积分饱和逻辑：如果本轮完整积分使候选输出超过本周期180°/s限速，则拒绝整轮积分。当前Ki6、dt20ms时，一次积分对应6*e*0.02°，单轮输出上限3.6°；|e|>30°时完整积分本身就超过限速。P/D趋于静止且输出追上不含新积分的值后，整轮拒绝会反复发生，形成自锁。该阈值是此恒定Ki配置下的解释，不代表恰好30°是所有场景的硬边界。

修复前主机复现e47.7/I-25.7，连续更新I始终-25.7。修复后同一状态在P/D不变时接受限速允许的3.6°积分贡献，输出逐轮推进。

## 修复方法

用上一轮输出、行程边界及每周期限速构造可达窗口。先计算不含本轮新积分的P+旧I+D输出，只接受本轮积分请求中能放入窗口的部分。

- 不再因整次请求过大而永久拒绝所有进展。
- 不因P/D本身超限而强行反向修改I。
- 真正输出行程限位仍禁止继续向外积分；误差反向时允许积分解除饱和。
- 继续执行原0～180°输出限幅和180°/s最终限速。
- saturated按完整请求与实际输出的差异标记，部分积分被限制时也能显示受限。

P0.7/Ki6/Kd0.005、死区、控制周期、IMU保护均未调整。修改适用于PID分支；DIRECT/FOLLOW逻辑不变。OLED改为 **HOLD Y PIDR2**，区分修正版与已保存PIDR。

## 验证

control_position、control、control_direct、app_integration四项主机套件通过。新增回归：

1. CSV对应e47.7/I-25.7，正反两种机械方向均能按限速推进，不再保持原I。
2. 恒定不可达输入下最终到行程边界，I停止继续累积；反向输入可立即离开边界。
3. 应用层固定50°误差时，输出在初次P动作后仍继续纠偏，避免仅核心修复但应用未生效。
4. ±50°参考模型（执行器0.04秒、机械增益1.1、无额外延迟）均在960ms进入±1°，未出现反向过冲。这不是50°实物测试承诺。

原fast假设288组仍最坏过冲1.127°、最慢进入1040ms；参考15°进入由修复前500ms变为480ms。原wide假设仍不通过：最坏过冲19.443°，最慢进入12920ms，不能声称解决全部高速定角稳定性。wide复核CSV保存于experiments/pidr_slew_fix/。

没有Keil编译/烧录，也未自动操控硬件。代码层冻结缺陷已回归验证，实物修复待用户验证。

## IMU_INVALID另查

这份CSV没有IMU_INVALID，不能把它与本积分缺陷视为同一原因。保护锁存时输出保持最后脉宽，先不要反复切换HOLD或复位丢失现场，发送：

```text
SERVO HOLD ?
IMU RAW ?
IMU FAULT ?
```

IMU FAULT ?读取首次故障时的原始数据及源；即使RAW已恢复VALID=1，也不能据此认为此前没有失效。AXIS_PROJECTION/通信/过期等仍需依据现场分别诊断。本次没有放宽保护。

## 用户验证顺序

1. 用户Keil Rebuild下载，确认HOLD Y PIDR2，底座水平、连杆90°、IMU牢固随连杆，静置校准。
2. 先复验静置20秒和慢速倾斜，确认没有破坏已通过行为。
3. 从约5°单次较快倾斜后停稳开始，记录CSV，不连续来回甩动；正常后再逐步增加至10°、20°。每次保持10秒，避免把仍在持续移动的底座当成停止后的恢复过程。
4. 反馈是否还会“无FAULT但大误差不继续纠偏”。实物过冲超过2°或持续摆动则停止HOLD并反馈；不要直接测试80°或撞限位。
5. 如出现IMU_INVALID，按上面三条查询保存故障现场，单独处理。
