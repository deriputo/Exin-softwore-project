# 第一项性能试验：HOLD输出限速180度每秒

Git试验标签：`v0.2.0-slew180-test`，分支`codex/hold-response`。
对照稳定版：`v0.1.0-stable`（提交`8d8b3eb`）。

## 改动范围

应用新增`APP_HOLD_SLEW_DEG_PER_SECOND=180.0f`，在App_Init中传给控制器。稳定版应用使用核心默认90度每秒，本版提高到180度每秒。核心通用默认仍为90度每秒。

控制周期20ms、方向-1、PID0.8/0.25/0.02、死区0.5度、IMU及PWM频率、0～180度硬限幅、故障保护均不变。此参数只限制HOLD闭环输出；MANUAL和串口SERVO SET不受本次调整影响。

理论上，限速生效时每20ms最多允许输出变化3.6度，原版是1.8度。它不是舵机实物速度测量，也不代表整个机构恢复时间减半。

## 已完成的软件检查

- 改动前控制测试通过。
- 改动后control、app_integration两组主机测试通过。
- 真实App测试在大姿态误差下，启动后第20/40ms脉宽分别为1460/1420us，每20ms变化40us，验证实际使用180度每秒配置；旧配置对应每20ms约20us。
- 当前应用参数的0/30/90/120/180目标、底座扰动、限幅限速和故障检查通过。
- 同一一阶机械模型下，8度底座阶跃恢复至1度内并保持1秒：90和180度每秒配置均为11780ms。此试验不能证明小扰动恢复加快；需进一步实测。

没有调用Keil编译或烧录，没有发送硬件运动命令。MCU编译、烧录由用户执行；实物效果待用户验收。

## 用户测试步骤

1. 若板上仍为稳定版，可先在HOLD90度下记录一组左右10度底座扰动，以及目标90→120→90的恢复表现，作为对照。每次动作幅度和速度尽量一致；不是稳定版时不要把结果当作该版本基线。
2. 在当前工程中打开Project/eXin.uvprojx，执行Rebuild并下载本试验版。底座水平、连杆90度竖直，IMU随连杆固定；上电静止至校准完成。
3. SERVO页长按K2开启HOLD，确认目标约90度。静置10秒，观察是否新增抖动或故障；随后沿控制轴左右各倾斜底座约10度并保持，观察动作起始、恢复时间、过冲和静止误差。
4. 回到水平，在HOLD中用编码器设目标120度，短按K2确认，稳定后再设90度确认。观察较大目标变化是否更快，是否摆动。此步不要退出到MANUAL测试，否则不会测到本次限速改动。
5. 可用串口助手分别发送SERVO TRACE ON和SERVO TRACE OFF采集；串口文本模式、实际CRLF结尾。目标侧ms用于分析，电脑接收时间不当作控制时间。
6. 反馈：恢复更快/差不多/更慢；静止是否抖动；是否过冲或持续来回摆；有无IMU_INVALID。出现持续摆动或跑向端点时关闭HOLD并反馈，不继续其他项目。

## 用户实物反馈（2026-10-15）

首轮反馈：恢复更快，无抖动、过冲或持续来回摆，无IMU_INVALID。随后补测：静置约10秒T=89.2、M=89.3，显示误差约0.1度；用户估计10度底座扰动恢复约0.28秒、无明显姿态偏差，但到位后会来回摆动。0.28秒尚未经板端日志量化，显示误差也不等于外部角度尺测得的真实精度。

因此暂不升级为稳定版，仍保留试验标签。已向用户询问：底座完全不动时，是摆几下衰减停稳、持续小幅摆动，还是逐渐变大，以及M变化范围。等待回答后决定抑振方法；当前没有继续提高P/I，也没有修改D或死区，不凭现象猜定参数。

下一项优先处理到位摆动，之后再判断是否需要提速；不同时修改多个因素。

后续用户澄清摆动最后会停止，并报告IMU_INVALID。故障查询时IMU已恢复VALID1/CAL1/AGE0/REASON NONE，但控制故障仍锁存；不能确认停止是自然收敛还是故障保持。已转入[首次故障记录测试](IMU_FAULT_CAPTURE_TEST.md)，限速及PID参数暂不再调整。
