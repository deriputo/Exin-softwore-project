# 手动响应复核与20ms诊断记录

版本：v0.12.3-response-trace20-test。用户确认trace15测试时底座固定，连杆及IMU真实随三次指令一起转动。

## trace15结论

378帧、18.85秒，板端时间间隔全部50ms；故障全NONE，P/I/D全0。记录起点已经是100°，后续三次完整变化如下，时间以第一帧为0。每段末1秒姿态中位数作为该段最终姿态，并非HOLD目标。

| 相对时间 | 手动指令 | 前1秒姿态中位数 | 末1秒姿态中位数 | 姿态/指令增益 |
|---|---|---:|---:|---:|
| 2.10秒 | 100→90° | 80.2° | 90.1° | -0.99 |
| 8.40秒 | 90→100° | 90.1° | 80.3° | -0.98 |
| 13.25秒 | 100→90° | 80.3° | 90.2° | -0.99 |

三次相对首条新指令记录，在后一帧（50ms后）均超过最终变化的90%。前两次出现相对末段稳态约0.7°的越过，第三次约0.1°。该试验支持小角度指令到姿态变化较快、符号为负、局部增益接近1；不支持把0.05秒当作精确物理延迟或直接指定一阶时间常数。新指令记录前已可能开始运动，姿态融合和内部PWM延迟都未分离。

数据并非单调一阶阶跃响应；50ms采样下多数运动发生于两帧之间。不能据此声称任意负载、大角度、速度和电源条件下都有相同响应。原较宽失配模型继续保留，不为使参数通过而缩小模型范围。

## 本轮筛选结果

临时控制模型增加比例项一阶滤波，P=1/1.5/2/3/4、Ki=4/6/8/10/12/16、Kd=0/0.005/0.01、比例滤波0.01/0.02/0.04/0.06/0.08秒，共450组。未改变活动控制源码。

沿用RATE有限假设：时间常数0.01/0.02/0.04/0.08秒、增益1/1.1/1.2、指令延迟0/20ms、姿态与角速度延迟均0/20/40ms、100ms完成±5/±30°倾斜，共288场景。失败时提前停止，CSV的cases、overshoot、entry只表示已经检查到的范围。没有候选同时通过2°过冲、10秒内进入±1°保持和12组连续跟踪均优于当前RATE。不能把失败候选在单一参考模型的较低RMS称为合格版本。

本轮只证明所筛选组合未通过这些假设下的检查，不证明所有比例控制或所有控制算法都无法达到目标。实验脚本tools/screen_proportional_response.py使用临时文件，不写控制参数、不访问硬件。

## 唯一固件改动

电脑USART1的TRACE周期50ms改为20ms，名义50Hz。格式不变；蓝牙仍200ms。控制周期仍20ms、IMU采样仍10ms、PWM仍50Hz、P0.7/Ki8/Kd0.005及±0.5°速度贡献均不变，100ms陀螺仪接续及所有故障保护不变。运动积分实验仍关闭。

TRACE每行缓冲区192字节，理论最大191字节×50条=9550字节/秒，低于115200 8N1的11520字节/秒；实际记录更短。命令回复优先、串口环形缓冲全行入队和非阻塞逻辑保留。满队列时仍可丢整条TRACE，必须检查实际板端时间间隔；名义20ms不是硬实时采样保证。测试不通过修改串口同步阻塞来追求帧率。

这不是提速控制版，不能报告控制性能已改善。当前先完成诊断，让下一轮对响应、尾段回落以及短时限速的判断有更细记录。

验证：实际Application/协议/控制器整合测试通过，独立1秒窗口实际发送50条电脑TRACE，含双串口、Sleep唤醒、长时间记录和保护回归；上位机3项、离线分析器5项测试通过。主机测试的tx数组是已发送文本的历史日志，因50Hz长时间记录扩大为1MiB；开发板512字节串口环形队列未扩大。未编译或烧录MCU固件，实物记录频率仍待用户下载后确认。

## 用户测试

1. 用Keil Rebuild并烧录本版（由用户执行）；上位机USB串口115200，底座固定，静止校准完成。关闭HOLD，设置手动90°。连杆与IMU安装保持不变。
2. 点击TRACE ON及开始记录CSV，先静置5秒。
3. 发送SERVO SET 100，等待5秒；再发送SERVO SET 90，等待5秒后停止记录。不要移动底座或同时操作编码器。
4. 提供CSV。先核对ms列大多相邻20ms，再估计10%/90%跨越区间、回落及稳态；即便20ms记录也不称为精确的真实轴角反馈或纯执行器辨识。
