# 200ms陀螺仪接续独立测试版

版本v0.15.0-imu-bridge200-test。用户在了解延长接续会增加估计漂移风险后批准本轮试验。上一版v0.14.0-smooth-deadband-test（100ms预算）及同名ZIP独立保留。

## 触发证据

用户在持续转动底座时，trace20csv约50.90秒首次记录IMU_INVALID。首次故障现场为：

```text
LAST_FAULT=IMU_INVALID AT=91605 SRC="GRAVITY_TIMEOUT" AGE=0 VALID=0 CAL=1 COUNT=200 AX=+370 AY=+1186 AZ=+40 mg OUT=1730us REFAGE=110 GYROCLIP=0
```

当时加速度模长约1.243g，大于可信重力上限1.2g；最后一次可信重力距故障已有110ms，超过原100ms预算。AGE=0表示故障帧新鲜，GYROCLIP=0表示该帧未检测到陀螺仪饱和；不能据此排除所有此前的通信或硬件干扰。故障后RAW恢复VALID=1不自动解除控制器故障。

这组现场记录支持重力参考中断超时这一直接原因，但单帧数据不包含整个中断期间的原始传感器序列，不能完整重放真实运动，也不能证明传感器硬件一定正常或异常。

## 唯一控制行为变化

IMU_GYRO_BRIDGE_MS从100改200。必须已经校准、有先前可信重力参考、当前帧可用且样本连续，才允许纯陀螺仪接续；预算仍从最后一次可信重力计时，不因每个新拒绝帧刷新。恰好200ms可接续，超过200ms判无效，仍由HOLD锁存并保留最后脉宽。

以下保持原样：

- 可信重力幅值0.8～1.2g和控制平面投影门限；1.243g仍不参与重力姿态校正。
- 单次积分样本间隔上限100ms、控制样本过期100ms、全零或异常范围帧、陀螺仪饱和判据。延长重力预算不等于允许200ms没有新数据。
- 校准流程及200个校准样本、静止校正±3%条件、0.5秒/静止0.1秒融合参数、6°/s静止加速校正上限。
- PID增益、0.5～0.8°平滑死区、限幅限速、20ms控制/电脑TRACE、200ms蓝牙TRACE，以及RTC/电源等其他功能。
- 故障锁存；传感器恢复不会自动重新使能控制器。

纯陀螺仪期间跳过加速度校正。本版只是容忍更长的短时干扰，不提高正常状态控制速度，也不保证真实快速运动时姿态误差或停止后过冲始终小于2°。无可靠重力校正的时间更长，零偏、噪声和模型/安装误差可能累计更多，恢复后可能回调，因此必须验收。

## 版本核对

OLED的HOLD标题为HOLD Y S200。IMU RAW ?末尾新增BUDGET=200，单位ms。原REFAGE仍是距上次可信重力的毫秒数，BRIDGE是累计接续帧数，不是持续时间或预算。SETTLE=0/1仍表示静止加速校正，本版没有修改其判据。

## 软件验证

23项C主机回归通过。核心检查包括：

- 原低平面投影以及1.3g不可信重力，持续10ms连续采样至200ms仍有效，210ms无效；每个拒绝帧不能刷新预算。
- 采用本次故障加速度形态370/1186/40mg，并另给人工100°/s陀螺仪输入：110/200ms保持gyro-only，不使用不可信重力校正，201ms无效且不继续积分。陀螺仪输入是人工测试值，不是声称恢复了故障瞬间未知的真实角速度。
- 可信重力恢复后才刷新预算；时间戳回绕仍正确。
- 采样间隔101ms、零帧、正负陀螺仪饱和、未校准时接续依旧拒绝。
- 真实IMU核心连当前HOLD控制器：200ms内继续调控，超时锁存、脉宽保持；超时后恢复传感器不自动重启。另测重力中断110ms后及时恢复，HOLD可以连续运行，无需重开。
- 实际应用的BUDGET回复、新页面标识、210ms故障现场REFAGE，以及原小误差平滑行为继续检查。

主机通过只验证边界和状态逻辑，不代表真实运动精度通过。原更宽延迟模型的未通过状态也没有因本轮改预算而改变。

## 用户验收

1. 用户Keil打开Project/eXin.uvprojx，Rebuild后烧录；保持机构静止完成校准，确认HOLD Y S200及RAW的BUDGET=200。编译和烧录由用户执行，本轮没有自动操作硬件。
2. 先HOLD静置20秒，确认没有新增抽动或故障。随后开启TRACE/CSV，先小幅慢速往返，再以此前容易触发故障的速度做适量往返，避免直接撞机械端点。
3. 最后把底座支撑放稳至少10秒再结束记录；说明大致停止动作的时刻，观察恢复后是否多出回摆、静止误差或抽动。
4. 如再次IMU_INVALID，安全允许时保留故障状态，关闭HOLD/复位前依次采集SERVO HOLD ?、IMU RAW ?、IMU FAULT ?。新的GRAVITY_TIMEOUT应结合REFAGE与BUDGET判断；也可能是其他原因，不能继续自动延长预算。
5. 若故障减少但出现持续摆动、明显漂移或停止后超过已约定2°的过冲，反馈并回退v0.14.0；不能仅以没有FAULT认定通过。

当前任务只修改接续预算和识别信息，没有合并此前暂缓的IMU静止窗口±5%改动。
