# OLED差异刷新验收

版本：`v0.3.0-oled-dirty-test`，基于`v0.2.1-imu-fault-test`及后续现场记录提交。稳定回退点仍为`v0.1.0-stable`。

2026-10-16：用户确认本项验收成功并要求继续下一项。本确认不代表IMU_INVALID修复，也未提供单项RAM占用或实测刷新耗时。

## 改动

原版每次Present发送全部1024字节显存；新版与已成功发送的画面比较，只发送变化的16字节块。画面完全相同则不发显示事务；一个块变化发送16字节显存数据，此外仍有地址/控制字节开销。此为软件模型验证的传输减少，不是实物响应时间测量。

新增1024字节画面记录和64字节有效标记，额外静态RAM1088字节；无动态内存。绘图API、100kHz I2C、16字节事务上限、IMU调度优先顺序、应用刷新周期均保留。

首次初始化和通信恢复必须全屏刷新，不能把未发送的零值视为已经显示。亮屏时重新发送最新完整画面。普通切页比较所有区域，包括旧文字的擦除。通信失败不确认画面已发送；重新初始化后丢弃全部旧有效标记。发送中新的绘图不会改动当前快照，后续刷新采用最新画面。

本版没有修改PID、姿态解算、HOLD限速/保护、按键、串口指令。IMU_INVALID仍是未解决的已知问题，不以局部刷新作为其修复结论。

## 软件验证

- `display_imu_state`通过：初始64块完整发送；单块变化仅发1块；连续两帧快照不混淆；相同画面不发数据；擦除旧像素；唤醒完整恢复；发送失败后初始化恢复全部画面；刷新中途熄屏及熄屏期间绘图；共享总线IMU仍能采样。
- `app_integration`通过：应用界面、60秒熄屏及首次唤醒手势、双串口、RTC写入顺序、TRACE与蓝牙唤醒回归。
- 主机替身测试不等于真实硬件测试。未由助手执行Keil编译/烧录；用户编译后核对RAM占用，等待实物验收。

## 上板步骤（用户执行）

1. 在`Project/eXin.uvprojx`执行Rebuild，确认0错误，关注链接RAM占用，再下载。无需修改接线或工程源文件列表。
2. 先保持MANUAL，检查开机动画、菜单、RTC时间连续更新是否正常；本项无需开启HOLD。
3. 来回切换时间、闹钟、IMU、舵机页面各数次。重点检查旧文字是否擦除、有无残影、缺行或花屏。
4. 转动编码器修改参数并确认，检查数字变化和选中标记。查看IMU页，确认数值持续更新。
5. 无操作等待60秒熄屏，再按一次按键唤醒。应恢复完整页面，第一次按键只唤醒；再按才执行页面操作。
6. 用原先已验收的串口查询指令检查收发，期间观察OLED是否仍更新。

请反馈：编译结果及RAM占用、切页/数字有无残影、唤醒是否完整、操作时是否感觉更流畅。若不通过，保留现象和所在页面，再决定是否回退；不同时调整控制参数。
