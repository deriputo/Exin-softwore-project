# 双键关闭本次闹钟提醒

版本：`v0.19.0-alarm-two-key`。前版`v0.18.1-pc-hidpi`已保留Git标签和独立ZIP。

仅修改Application/app.c的按键消警逻辑和OLED报警提示。底层20ms消抖、5ms扫描、长按阈值、RTC闹钟调度、舵机定角、上位机/蓝牙均不变。

## 操作

报警时，K1与K2消抖后同时处于按下状态即停止本次提醒，不要求两次PRESS事件时间相同，也不要求同时长按1秒：

- 两个键一起按下：消警。
- 按住K1，再按K2：消警。
- 按住K2，再按K1：消警。
- 单键短按、单键长按、按完K1松手再按K2：继续报警。

报警期间按键不执行页面操作。消警动作中的短按、长按、松手被消耗，两个键都松开后恢复正常操作；若只松开一个又按回，仍不执行菜单动作。已经按住双键时闹钟开始，也会消警。

OLED提示`ALARM! K1 + K2`与`BOTH TO STOP`。关闭的是本次活动报警；若多个闹钟同时活动，一并确认。保留原有启用状态和下次调度，不等同ALARMn OFF或DEL。

## 实物测试（用户编译烧录）

1. 在Keil打开Project/eXin.uvprojx，Rebuild并下载，随后复位。上位机不需要更新依赖。
2. 用OLED或上位机设置一个约15秒后触发的闹钟，等待报警提示与PB0报警灯闪烁。
3. 短按K1、短按K2，分别长按超过1秒：均应继续报警，页面/舵机/HOLD不变。
4. K1按下并松开，再单独按K2：仍应报警。
5. 按住K1不松手，再按K2：报警灯应停止闪烁并熄灭，OLED出现ALARM STOPPED；无需等1秒。
6. 两个键先后松开，页面不应跳转；完全松开后再次单独短按K1，应恢复正常切页。
7. 重新设闹钟，测试反方向“先K2后K1”，以及双键一起按；均应消警。可在舵机页面存在未确认编辑值时验证，消警不得确认该角度或切换HOLD。

应用集成测试已覆盖：两键不重叠、长按第一键后第二键加入、先后顺序互换、错开松手不误操作、未确认舵机编辑值不提交、双键已按住时报警、多个活动报警确认。key_core和rtc_core检查也通过。以上是主机模拟验证，Keil编译和实物验收由用户完成。
