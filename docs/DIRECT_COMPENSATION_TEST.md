# 连杆姿态直接补偿试验

版本`v0.8.0-direct-compensation-test`。用户要求停止逐步增加Ki，希望底座停下时已基本补偿到位，授权单独做一版。IMU仍固定在舵机驱动的连杆上，不改为底座跟随。手动90→100用户估计约半秒到位，这只是时间量级参考，并非精确标定。

## 新旧逻辑

保留CONTROL_MODE_PID和全部PI配置；新增CONTROL_MODE_DIRECT。本版应用选择DIRECT，OLED显示`HOLD Y DIRECT`。不是将原位置式PID每轮直接累加。

每次有效20ms更新：

```text
估计位置 += dt / (0.30 + dt) * (上一轮限幅限速后的指令 - 估计位置)
误差 = 目标姿态 - 连杆IMU实测姿态
若 |误差| > 0.5°：
    补偿量 = 0.5 * 误差
    候选舵机指令 = 估计位置 + 安装方向 * 补偿量
否则：
    候选舵机指令 = 上一轮指令（保持，不退回滞后的估计位置）
候选指令继续经过原有输出限幅及180°/s限速
```

估计位置来自上一轮指令的一阶响应模型，不是舵机编码器实测位置。时间常数0.30秒不等于0.30秒到位，也不是用手动半秒反馈精确反推的标定结果。补偿系数0.5是保守试验值，不能承诺一次动作即无误差。

HOLD开启时先将估计位置设为当前指令，假设此前手动动作已停稳。若刚发完手动角度马上开HOLD，该假设可能不成立，所以本轮要求手动回90并停稳后再开。关HOLD/故障时保持最后脉宽；无效/重复样本不继续推进模型。重新开启HOLD重新初始化参考，重复ON不重捕获。

方向仍-1（指令增大时Y姿态减小），20ms周期、0.5°死区、0～180°目标/输出、180°/s限速、故障锁存均保留。IMU安装映射/滤波未改。PI配置中的Kp、Ki、Kd在DIRECT中不参与输出，不把这版称为原PI又调了一组参数。

## TRACE说明

标准命令、HOLD ?和CSV列格式保持兼容。target/measured/error/servo/saturated/fault含义不变。DIRECT中P列表示`0.5*姿态误差`的候选位置补偿量，死区内为0；**不是旧PI的Kp*误差**。I/D均0。servo是最终指令，不是实测轴角；当前CSV没有估计位置字段，不能用bias-P公式反推出DIRECT全部内部状态。上位机仍能绘图、记录及分析姿态误差。

OLED必须看到`HOLD Y DIRECT`再测，便于排除误刷旧版。Keil工程源文件列表不用改变，新实现位于原control.c中。

## 用户编译与验收

1. 保持HOLD关闭，底座水平、连杆手动90°对应竖直、IMU随连杆固定。用户Keil Rebuild并下载，等待校准完成；助手未执行MCU编译或烧录。
2. 等手动动作停稳，开HOLD，目标约90°，确认OLED显示`HOLD Y DIRECT`，HOLD ?为ON/FAULT=OFF。先静置20秒。
3. 静止正常后开始TRACE记录，另存trace_direct_5deg.csv。水平2秒，使用固定支撑倾斜约5°，放好松手后不再碰底座，记录15～20秒，不在末尾回正。前后直接查询HOLD ?，不重新开启后代替原状态。
4. 提供CSV，并描述松手后的明显尾调是否减少、是否反复摆动或过冲。如果静止持续摆或动作明显恶化，关闭HOLD，不继续放大角度。
5. 仅在小角度通过后再另测15°，先不测试端点或80°极限。若IMU_INVALID，保存IMU FAULT ?首次记录，不能把锁存停机算作到位。

本版尚未实物验收，不保证达到“几乎一步到位”。如果模型不匹配明显，需要基于实际数据再校准时间常数/补偿系数，不一次改动多个因素。
