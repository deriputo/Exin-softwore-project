# HC-04 蓝牙串口

本工程按用户资料中的 HC-04 / HC-04S 透传模块实现，保留电脑 USART1，新增 USART3。使用 SPL、中断与两个独立 512 字节收发环形缓冲区，不使用阻塞收发。接收错误/溢出时丢弃损坏命令至换行，避免执行截断指令。

## 接线

| 模块引脚 | STM32 接线 |
|---|---|
| TXD | PB11 / USART3_RX |
| RXD | PB10 / USART3_TX |
| GND | STM32 GND，共地 |
| VCC | 手册裸模块要求 3.3 V，供电能力至少 100 mA |
| KEY、STATE | 透传控制无需连接，不按住模块配置按键 |

若是带稳压底板的成品模块，VCC 电压按该底板标注；不能把裸模块直接接 5 V。UART 信号电平为 3.3 V。PB8/PB9 的 OLED/IMU、PA2 的 KEY2 和 PA9/PA10 的电脑串口继续使用原接线。USART2 的 PA2 与 KEY2 冲突，所以选 USART3。

## 参数与手机

`bluetooth_config.h` 默认波特率 9600、8N1，与手册出厂值一致。若模块以前改过波特率，应把模块与驱动配置统一。程序不自动发送 AT 命令，也不修改模块参数。

模块上电后等待至少 300 ms 再发送数据。手机通过资料中的蓝牙串口应用/小程序连接；BLE 默认名称 HC-04LE，经典蓝牙默认名称 HC-04、配对密码 1234。支持 BLE 的应用中默认服务 UUID 为 FFE0，透传特征为 FFE1，需要开启接收通知。实际名称、密码和 UUID 以模块当前配置为准。

手机选择文本/ASCII 发送，并打开“发送新行/追加 CRLF”，发送 `HELP` 测试。命令与电脑串口完全相同，例如 `TIME(14:30:05)`、`ALARM1(07:00:00)`、`IMU ?`、`SERVO SET 90`、`SERVO HOLD ON`。不添加教程演示中的 `@` 等包头；每条命令必须以真正 CR、LF 或 CRLF 结束，不能发送字面上的反斜杠转义文本。

注意两类指令的结束符相反：手机给 STM32 的应用命令需要换行；HC-04 的 AT 设置命令不带回车换行。AT 设置应使用独立 USB 转串口在模块未连接时操作，避免两个 TX 输出同时连接同一个 RX。

## 双路行为

两路分别保存接收行、命令队列、回复缓存和 TRACE 开关。电脑请求回复给电脑，手机请求回复给手机；两路控制同一设备，命令按主循环调度顺序执行。RTC 异步写入完成前暂停另一通道命令处理，避免时间写入互相覆盖。某一路 TX 队列繁忙时缓存该路回复，另一通道可以继续工作。

电脑 `SERVO TRACE ON` 为 20 Hz；蓝牙为 5 Hz（`APP_BLUETOOTH_TRACE_PERIOD_MS=200`），适配 9600 波特率。TRACE 优先让出容量给命令回复，队列满时丢弃整条跟踪记录，不阻塞控制。两路分别 ON/OFF，查询返回该路状态。

60 秒无操作后继续进入普通 Sleep；蓝牙收到字节会恢复 OLED 并执行指令。第一按键唤醒整次手势屏蔽规则保持生效。真实 Standby 的可选保护也检查蓝牙队列、协议状态和 USART3 待处理接收标志。

当前四线接法不检测连接状态。断线时未结束的半条命令仍留在 STM32；重新连接先单独发送一次换行（可能得到一次 ERR SYNTAX），再发送完整 HELP。不能用蓝牙数据包边界或短暂接收停顿判断命令结束。

## 上板验收

1. 接好四根线并烧录新版固件，连接手机，带换行发送 HELP，应收到命令列表。
2. 手机设置 TIME，同时电脑查询 SERVO，确认各自接收对应回复。
3. 手机设置闹钟、查询 IMU、设置舵机、开关 HOLD，行为应与电脑一致。
4. 两端分别开关 TRACE，检查手机约 5 Hz、电脑约 20 Hz，互不关闭。
5. 等待 60 秒熄屏，再发手机命令，应恢复显示并执行；按键首次唤醒不切页、不确认。

资料依据：用户提供的 HC-04 用户手册 V2.6（2023-12-12），第 2–5 页引脚、电气和默认参数，第 11 页 BLE UUID；资料示例 Serial.c 的 9600 设置。当前软件测试和 Keil 编译已完成，无蓝牙实物连线测试或烧录。
